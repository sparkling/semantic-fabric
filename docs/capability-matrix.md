## Release-blocking limitations

- **l-authz (ADR-0018)** — Explicit public bearer service-principal admission, request-context propagation, isolated caches and allow/deny traces exist. Row-level RLS, portable ABAC, external sensitivity, end-user identity, policy-aware hot reload and access-decision metrics remain incomplete.
- **l-config-layering (ADR-0011)** — Environment-referenced source values exist, but the validated defaults/TOML/env/secret-store configuration model is not implemented.
- **l-deadline-cancellation (ADR-0010)** — Owned serving SQLite cancels its pre-worker admission wait and interrupts active VM work after mutex acquisition. It does not pre-empt raw standard-mutex wait, already-submitted/running blocking work, busy timeout, blocking UDF/VFS/I/O, detached compiler CPU, raw/conformance work, or establish common database-native statement cancellation.
- **l-describe (ADR-0055)** — SQLite has required one-target-expression, one-hop outgoing DESCRIBE endpoint evidence with RDF-graph set union. A variable may resolve to several resources and repeated resources collapse. Multiple projected targets, unbound target variables, LIMIT/OFFSET Slice shapes, source-backed OrderBy, recursive blank-node closure and PostgreSQL/MySQL execution remain unqualified.
- **l-federation (ADR-0040)** — Only the accepted ADR-0006 non-blocking vertical exists: exactly two distinct source-affine one-triple SELECT UNION arms stream sequentially. Cross-source joins, blocking/global operators, reducers, spill, more sources/backends, consistency vectors, performance qualification and production admission remain unavailable; proposed ADR-0040 is not accepted.
- **l-global-operators (ADR-0040)** — The finite root variable-key ORDER window is qualified by bounded compaction, independent row/payload ceilings, controlled heap/RSS, a materialized semantic oracle and the live Product Mock serve path. Expression ORDER, GROUP, solution/term DISTINCT, graph dedup and broader bounded global physical execution remain unavailable.
- **l-lateral (ADR-0007)** — The parser feature recognizes LATERAL, but both compiler paths reject it and no execution profile is implemented.
- **l-live-optional (ADR-0055)** — The PostgreSQL/MySQL evidence can skip on provider absence and therefore cannot establish production admission.
- **l-metadata-toctou (ADR-0055)** — Authored-R2RML result-column probes and later branch emission still permit intervening DDL. The private PostgreSQL Direct Mapping path separately holds one protected repeatable-read transaction from exact generation observation through mapped request execution and final recheck; its public promotion and every other source path remain unqualified.
- **l-mysql-source-test (ADR-0055)** — The MySQL source-selector branch lacks a positive open_backend selector test.
- **l-observability (ADR-0011)** — Fixed liveness/readiness endpoints, bounded three-phase shutdown, a closed payload-free Serve-only JSON request/compiler trace slice and an opt-in three-metric Prometheus slice are implemented. The remaining ADR-0011 metric catalogue, OTLP, SLO/overhead qualification, layered configuration, verified TLS, automatic source-health policy, adapter-internal sf-sql spans and complete cross-backend cleanup remain unimplemented.
- **l-path-resource (ADR-0049)** — Recursive property paths use an exact finite-pair fixed point, but total work/cancellation budgets and live PostgreSQL/MySQL qualification remain open.
- **l-postgresql-synthetic-row-identity (ADR-0007)** — Compiler-only no-primary-key path SQL maps the synthetic `rowid` sentinel to snapshot-local PostgreSQL `ctid`; a real `rowid` column still collides and live PostgreSQL path execution is not evidenced.
- **l-product-mock-live-drift (ADR-0048)** — Mutable product-mock PostgreSQL is an optional development differential. Its table/column inventory currently rejects drift and grants no backend admission.
- **l-production-admission (ADR-0055)** — The complete backend contract, live matrix, security, cancellation and conformance gates in ADR-0055 v1 are incomplete.
- **l-protocol (ADR-0019)** — No pinned SPARQL Protocol manifest is executed; the tested read-only HTTP subset accepts exactly one query parameter for GET/form POST or one raw query body, rejects dataset/version/extra parameters, and is not full Protocol conformance.
- **l-query-budget (ADR-0010)** — The serving lane shares one absolute deadline and finite ceilings for observable metadata probes, branch opens, pull attempts, semantic result items, serializer writes and ORDER textual-payload high-water growth; an independent row window bounds fixed per-row ORDER overhead. These are not a total heap ceiling. Compiler CPU, database rows scanned, recursive SQL iterations/source cost, raw/conformance callers, common source-native statement cancellation and atomic/no-prefix post-200 responses remain outside total M2 QueryBudget.
- **l-release-artifact (ADR-0055)** — Narrow private diagnostics include same-byte static RootPie preflight, a counterfactual non-authority bubblewrap name/path inventory, and late seccomp; the minimal production dependency closure and ADR-0055 exact-artifact smoke/SBOM/signature/provenance bundle are not implemented and remain v1 blockers. Exhaustive host byte-consumption/runtime-closure proof remains open post-1.0.
- **l-schema-lifecycle (ADR-0007)** — Authored-R2RML startup semantically validates before activation and quarantines unverified constraints and type-authorized pooling. A private PostgreSQL Direct Mapping path now derives and binds one exact observed generation, revalidates every request on its lease, and has passing 16.9/16.15 observation-profile receipts; public promotion, typed synthetic row identity, a general off-path reload-candidate lifecycle and other backend generations remain unimplemented.
- **l-semantic-admission-scope (ADR-0050)** — ADR-0050 is accepted as the lifecycle design, but its wider runtime phases remain incomplete. The implemented generic gate is the bounded sealed four-rule Product Mock contract for mandatory ontology plus effective authored-R2RML mapping. Private PostgreSQL Direct Mapping generation is separately validated and bound under required-live evidence, but public Direct Mapping promotion, generalized SHACL, other backend generations, detailed reports and production admission remain outside this slice.
- **l-semantic-builder-gold-source-development (ADR-0048)** — Canonical semantic-builder gold and the sealed semantic-product-mock source are development authorities. The sealed relational facet covers 148 TriplesMaps/721 predicate-object maps over 112 tables/598 columns, but proves neither full live-inventory conformity, image/source provenance nor backend admission.
- **l-snapshot (ADR-0055)** — Immutable request leases, sealed full-state publication, revision/shutdown fencing and one dormant closed PostgreSQL Direct candidate/control lifecycle exist. General multi-profile reload, other backend-generation lifecycles, public reload, credential/config hot reload and PostgreSQL Direct Mapping promotion are not implemented.
- **l-sqlite-admission (ADR-0010)** — SQLite serving admission caps active leased work per physical connection and each waiter is deadline/cancellation-bound. Raw pool/mutex users bypass it, round-robin is not availability-aware, and the standard mutex plus submitted/running blocking work remain non-cancellable.
- **l-stream-error-atomicity (ADR-0011)** — Post-200 SELECT/CONSTRUCT failures terminate the body and may expose a usable prefix; they cannot become RFC 9457 responses.
- **l-transport-security (ADR-0014)** — Remote-source TLS verification and a production secret-store transport remain unimplemented.
- **l-verified-source-generation-promotion (ADR-0051)** — The private PostgreSQL Direct generation lease and independently reviewed dormant control lifecycle have required tests, and exact PostgreSQL 16.9/16.15 observation-profile receipts pass. Public startup still rejects Direct Mapping before connector I/O pending explicit promotion and the remaining runtime-admission gates.
